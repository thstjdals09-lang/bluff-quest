# BLUFF QUEST — First Playable Prototype

포커의 블러프·상대 읽기·위험과 보상을 판타지 세계의 심리전 어드벤처로 재해석한 싱글플레이 게임의 첫 번째 Vertical Slice입니다. (BLUFF QUEST는 임시 작업명)

기획 기준 문서: `BLUFF_QUEST_GDD_v0.2.md` (저장소 루트)

## 실행 방법

```bash
npm install
npm run dev        # http://localhost:5199
```

- 타입체크: `npm run typecheck`
- 테스트: `npm test`
- 프로덕션 빌드: `npm run build` → `dist/`

## 조작

- 이동: 방향키 / WASD / 화면 D패드 (모바일)
- 상호작용: E, Space, Enter 또는 하단 상호작용 버튼 (대상에 인접했을 때)

## 개발자 툴

- 개발 서버(`npm run dev`)에서는 화면 우하단 **DEV** 버튼이 자동 노출됩니다.
- 프로덕션 빌드에서는 URL 뒤에 `?dev`를 붙여야 노출됩니다. (예: `https://.../index.html?dev`)
- 탭: A 상태 조회 / B 상태 제어 / C 대결 디버그(시나리오 강제 시작·내부 정보) / D 세이브(강제 저장·초기화·JSON 내보내기/가져오기) / E 이벤트·오류 로그

## 구조

```
src/
  assets/          # AI 생성 이미지 에셋 (배경 플레이트·캐릭터·오브젝트 스프라이트)
  game/            # 게임 로직 (UI와 분리, 순수 함수 위주)
    types.ts       # 상태·액션·콘텐츠 타입
    state.ts       # 순수 리듀서 (모든 상태 변경의 단일 통로)
    encounter.ts   # 대결 엔진 (결정론적 상태 기계, NPC 공용)
    save.ts        # localStorage 저장/복원/검증/백업/마이그레이션
    rng.ts         # 시드 기반 PRNG
    log.ts         # 개발자 로그
    devview.ts     # 공간 디버그 오버레이 플래그 (개발 모드 전용)
    content/       # 콘텐츠 데이터 (코드 로직과 분리)
      scenarios.ts # 고블린 상자 대결 시나리오 4종
      world.ts     # 지역 논리 그리드·아이템·퀘스트 정의
      scenes.ts    # 비주얼 씬 정의 (배경·스프라이트·원근 투영)
      dialogues.ts # NPC·조사 대상 상호작용 트리
    __tests__/     # vitest 단위 테스트
  ui/              # React 컴포넌트 (렌더링만 담당)
    SceneView.tsx  # 탐험 씬 렌더러 (배경 플레이트 + Y-sort 스프라이트)
```

## 탐험 비주얼 시스템

- **논리/비주얼 분리**: 이동·충돌은 `world.ts`의 그리드가 담당하고, 화면 표시는
  `scenes.ts`의 원근 사다리꼴 투영(`projectToScreen`)이 그리드 좌표를 화면 %좌표와
  스케일로 변환한다. 세이브 데이터에는 그리드 좌표만 저장된다.
- **깊이 정렬**: 모든 스프라이트(플레이어·오브젝트)는 발 위치의 화면 Y좌표로
  z-index를 계산해 앞뒤 가림이 자동 처리된다 (예: 중앙 상자 더미 뒤로 걸어가면 가려짐).
- **에셋 교체**: 배경 플레이트·스프라이트는 `src/assets/`의 이미지 파일만 바꾸면 되고,
  배치·크기·원근은 `scenes.ts` 데이터로 조정한다. 새 지역 추가 시 배경 1장 + 투영
  파라미터 + 오브젝트 목록만 정의하면 같은 엔진으로 동작한다.
- **세이브 마이그레이션**: v1(이모지 타일맵) 세이브는 로드 시 v2로 자동 마이그레이션되어
  진행(퀘스트·아이템·대결 상태)은 보존되고 위치만 새 좌표계의 시작 지점으로 재배치된다.

## 장소 연결 구조 (고블린 시장 기획서 v0.5 — 1단계)

- **장소(Location)와 지역(Region) 분리**: 각 장소는 `regionId`, 기획 코드(GM-01 등), 첫 방문 안내,
  출입구 목록(`exits`)을 가진다. 출입구는 `kind: 'exit'` 엔티티 + 목적지·도착 좌표·방향·해금 조건.
- **이동 방식**: 출입구에 다가가면 목적지가 표시되고(`→ 오래된 창고`), 상호작용 버튼으로 이동한다.
  이야기가 걸린 문(프롤로그 중 시장 문, 잠긴 창고 문)은 기존 대화·사건을 그대로 연다.
- **연결 검증**: `validateLocationGraph()`가 출입구 짝, 도착 좌표, 양방향 연결, 지역 내 도달성을 검사
  (테스트 + 개발자 툴에서 실행).
- **지역 지도**: 월드맵 화면의 "지역 지도" 탭. 가 본 장소와 그곳에서 이어지는 장소만 보인다.
- **세이브 v6**: 장소 방문 기록(`visitedLocations`) 추가. 기존 세이브는 확실한 근거가 있는 장소만 추정해 채운다.
- 현재 연결: 시장으로 가는 길(GM-01) ↔ 입구 장터(GM-02) ↔ 오래된 창고(GM-02a), 밤의 부두 → 진입로.
  신규 장소(중앙 장터 등)는 다음 단계.

## 타이틀 · 계정 · 프롤로그 (Phase 6)

- **흐름**: 타이틀 → 계정 선택/생성(로그인) → 이어하기 또는 새 모험 → 승부사 이름 → 프롤로그
  → 고블린 시장.
- **계정 방식**: GitHub Pages 정적 배포(서버 없음)이므로 **기기 내 로컬 프로필**. 계정마다
  세이브 슬롯이 분리된다(`bluff_quest_save::<계정ID>`). 계정 도입 전 세이브는 최초 실행 시
  "여행자 (기존 세이브)" 계정으로 자동 승계된다. 기기 간 동기화는 제공하지 않는다.
- **프롤로그**: 시장으로 가는 길(신규 탐험 구역) — 낡은 스페이드 카드 발견(뒷면 경고문),
  입구의 상인의 반응과 말 바꾸기, 시장 입장 연출. 카드의 정체는 확정하지 않는다.
- **왕고블린**: 시장 게시판 포스터와 그리즐·미라의 서로 다른 평으로 소문만 노출(보스전 미구현).
- **기존 플레이어 보완 경로**: 카드는 소급 지급하지 않는다. 시장 남쪽 출구로 나가 길에서
  직접 발견할 수 있다(프롤로그 퀘스트는 새로 생기지 않음).
- **세이브 v5**: 플레이어 이름 추가(v1→v5 체인 마이그레이션).

## 스토리 통합과 항구 (Phase 5)

- **THE UNSEEN HAND 스토리 바이블 통합**: 그리즐의 검은 칩(친구와의 약속), 미라의 과거(전직
  딜러), 창고 장부 단서, 초대장의 의미가 실제 플레이 콘텐츠로 구현. 후반부 반전은 미노출.
- **선택과 결과**: 검은 칩 사건은 접근 방식(캐묻기 vs 우회 조사)에 따라 그리즐의 공개
  장면·관계가 달라진다(warm/cold). 소프트락 없음 — 어느 경로든 미라를 통해 진행 가능.
- **사기꾼들의 항구 수직 슬라이스**: 밤의 부두 탐험 구역 + 정보상 올드 핀. 핀은 게시판
  소문으로 손님을 떠보는 낚시꾼 — 게시판을 읽었다면 그의 블러프를 간파할 수 있고,
  정보의 값은 금화·배짱·초대장 공개(소문 위험) 중에서 스스로 정한다.
- **정보 기록 시스템**: 일지에 수집한 정보를 사실/주장/소문/추정으로 구분 기록
  (`content/records.ts`). NPC의 말은 확인 전까지 '주장'으로 남는다.
- **세이브 v4**: 단일 quest → 다중 quests 맵 (v1→v4 체인 마이그레이션, 기존 진행 보존).

## 모바일 게임 화면 구조 (Phase 4)

- **전체 화면 뷰포트**: 웹페이지형 카드 레이아웃을 제거하고 게임이 브라우저 화면 전체를
  사용한다 (safe-area 대응, HUD·조작은 씬 위 오버레이).
- **탐험 카메라**: 씬 월드를 뷰포트보다 크게 렌더링하고(`cameraZoom`) 카메라가 플레이어를
  따라가며 경계에서 클램프된다. 캐릭터가 화면 높이의 ~28%를 차지하고, 배경은 4K 업스케일본.
- **4가지 화면 모드**: 탐험(MODE A) / 대화(MODE B — NPC 클로즈업 일러스트) /
  심리전(MODE C — 전용 일러스트 위 상자 히트영역·행동 바) / 이벤트(MODE D — 발견 연출 카드).
  게임 로직·대결 엔진은 그대로, 표현 계층만 교체.
- **인게임 UI**: 검정·갈색 + 금색 프레임 테마. 좌상단 퀘스트 트래커, 우상단 지도·가방·일지,
  좌하단 홀드 이동 방향 패드, 우하단 상호작용 버튼.

## 월드 프레임워크 (Phase 3)

- **월드맵**: 5개 지역(고블린 시장·사기꾼들의 항구·유령 카지노·황금 도시·미지의 지역)을
  `content/regions.ts` 데이터로 정의. 지역 추가 시 데이터 항목만 추가하면 월드맵·상세·프로필에
  자동 반영된다.
- **구현 상태와 해금 상태 분리**: `impl`(playable/preview/unknown)은 개발 상태,
  `getRegionAccess`는 실제 게임 상태(플래그) 기반 해금. 항구는 초대장 발견 시 해금된다.
- **시스템 화면**: 일지(퀘스트 유형 6종 구분), 프로필(방문 지역·배지·모험 기록), 포커
  커리어(실제 대결 집계), 인물·관계(런타임 상태에서 관계 파생), 컬렉션(발견 기록과 보유 구분),
  특별 콘텐츠(승부사의 탑 등 제안 단계), 설정.
- **전역 내비게이션**: 하단 주요 메뉴 4개 + 더보기 시트.

## 세이브

- localStorage `bluff_quest_save`에 버전 필드를 포함해 자동 저장 (상태 변경 시·화면 이탈 시).
- 손상된 세이브는 백업 키로 옮긴 뒤 새 게임으로 안전하게 시작합니다.
- 진행 중인 대결(시나리오·공개된 단서)도 저장되어 재접속 시 그대로 이어집니다.
- 세이브 포맷 v3 — v1(타일맵)·v2(비주얼 씬) 세이브는 로드 시 자동 체인 마이그레이션되며
  진행(퀘스트·아이템·플래그)이 보존됩니다.
